These docs explain the projects that run the business. What each one does, how it is operated day to day, and what to do when something goes wrong.

They are written for people first. Plain words. Short pages. When a page needs a technical term, it explains the term the first time it appears.

## One page, one job

Every page is one of three kinds. Do not mix them on one page.

- **How-to**: do one task, step by step. Start with what you need, end with how you know it worked.
- **Reference**: the facts, laid out to be looked up. No stories, no opinions.
- **Explanation**: why something works the way it does, and what the trade-offs were.

## Adding a page

<Steps>
  <Step title="Write the page">
    Create an `.mdx` file with a `title` and a one-line `description` at the top.
  </Step>
  <Step title="Put it in the menu">
    Add the file path to `docs.json` under `navigation`. A page that is not in the menu cannot be found.
  </Step>
  <Step title="Run the check">
    ```bash
    bash scripts/check.sh
    ```
    It fails if a page is missing a title, is not in the menu, has a broken link, or contains something that looks like a secret.
  </Step>
</Steps>
