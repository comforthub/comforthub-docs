Every module below is mirrored between Zoho and Supabase. Almost all flow both ways. The interesting column is the last one: what happens here when someone deletes the record in Zoho.

| What a delete does | Meaning |
|---|---|
| **deactivate** | The row stays and is marked inactive. Nothing else is touched. |
| **delete** | The row is removed, along with only the child rows it owns. |
| **refuse and flag** | Nothing is written. A human-review flag is raised because this record moved money. The two systems now disagree until a person rules. |

|---|---|---|

| Accounts | yes | deactivate |
| Leads (prospects) | yes | deactivate |

## Two rules that apply to every module

- **A locked record in Zoho is a one-way door.** A change made here is skipped and noted, and nothing alarms. Unlocking is the office's call.
- **A change never bounces.** When the sync writes a record, it marks the write as its own so the other side does not push it straight back.
